Where AI Is Used & Why
✨
Gemini 3.1 Pro — AI Integration Points
Every AI usage is Google-ecosystem only (Vertex AI). No third-party LLMs.
Vertex AI  |  Gemini 3.1 Pro  |  Google Cloud
📧
1. Email Content Generation
Gemini 3.1 Pro • Core Feature
  • What: Generates personalized invite emails per participant using study context, methodology, and region
  • Why AI: Each email needs unique personalization — manually writing 15–25 emails per study takes 60+ min. AI reduces this to seconds
  • Why Gemini: Google-only ecosystem requirement. Gemini 3.1 Pro handles tone, structure, and variable injection with template-constrained prompts
  • Fallback: Pre-approved static template when Gemini is unavailable — no workflow stoppage
🧠
2. Intent Classification
Gemini Flash / Keyword Rules • Chatbot Router
  • What: Classifies RC commands into action types — SEND routes to Invite Agent, STATUS routes to Query Agent, unclear triggers clarification
  • Why AI: RCs type natural commands ("send 10 invites for case 1234567"). AI understands intent without rigid command syntax
  • Why Gemini: Gemini Flash is lightweight, fast (<200ms), and cost-efficient for classification tasks. Falls back to keyword rules if needed
  • Fallback: Keyword-based regex matching as backup — always functional
✅
3. Content Validation
Gemini 3.1 Pro • Quality Gate
  • What: Validates generated email content — checks template structure, variable substitution, tone consistency, and brand compliance
  • Why AI: Rule-based validation misses nuance — AI catches malformed sentences, missing variables, off-brand tone that regex can't detect
  • Why Gemini: Same model that generated the content can validate it — understands the expected output structure
  • Fallback: If validation fails, that specific email falls back to static template. RC is notified per-email
🚫
Where AI Is NOT Used (By Design)
Critical operations use deterministic logic — no AI unpredictability
📤
Email Dispatch
Deterministic — Salesforce API
  • Sending emails is a critical action — must be 100% reliable
  • Uses Salesforce SingleEmailMessage API directly
  • AI generates content, but dispatch is rule-based
🗄
Case Updates
Deterministic — Salesforce REST
  • Updating child cases, parent notes, ICF links
  • Structured data writes — no interpretation needed
  • Status transitions follow fixed rules
🔍
Candidate Filtering
Deterministic — Query + Filter
  • P0 selection is rule-based (status = P0, not already invited, ordered by date)
  • No AI judgment in who gets invited
  • Deduplication uses audit log lookup
📊
Audit & Reporting
Deterministic — Cloud SQL Queries
  • Metrics, SLA tracking, audit logs
  • Aggregation is SQL-based, not AI-generated
  • Numbers must be exact — no approximation

Error Handling & Circuit Breakers (14 Scenarios)
Input & Validation Scenarios
1.2 — Invalid Study ID
SF returns 404 → Block workflow → Inline error: "Study ID not found. Verify and retry." → Log failed attempt
1.3 — Concurrent RC Conflict
Multiple RCs detected on same case → Candidate-level locking prevents duplicate sends → RCs share access with coordinated deduplication
1.4 — Repeat Trigger (Already Sent)
Detect last run from audit log → Warn RC with details → Offer: send to newly shortlisted P0s only, or review previous run
2.4 — P0 Already Invited
Duplicate Guard checks audit → Auto-exclude invited P0s → Show: "3 P0s excluded — already invited on [Date]."
2.5 — P1 Invite Request
Out of scope → "P1 invitations not currently supported. Handle manually or wait for future version."
2.6 — No New P0 Candidates
Filtered list is empty → Abort gracefully → "No new P0 candidates for Study [ID] since last run on [Date]."
System & Dependency Failures
3.2 — Gemini Bad Content
Content validation catches errors → Hold email → Fallback to static template for that email → RC notified
3.3 — Gemini API Down
Circuit breaker triggers → Switch to approved static fallback → RC confirms: "Proceed without AI?" → Team notified
3.4 — Partial Send Failure
Per-email tracking → Auto-retry 3x (exponential backoff) → "12/15 sent. 3 failed." → Dashboard shows failed list
3.6 — RC Cancels Mid-Send
Stop remaining → Already-sent NOT recalled → "8/15 sent. 7 not sent. Cases updated for sent only." → Audit logged
4.3 — Parent Case Update Fails
Retry 3x with backoff → If all fail: "Child cases created. Parent case update failed — update manually." → No rollback
5.1 — SLA Breach (>15 min)
Amber warning at 10 min → Red escalation at 15 min → Team notified → Incident logged in audit trail
6.2 — Shortlisting App Down
Hard blocker → "Shortlisting App unavailable. Cannot retrieve candidates." → Workflow aborted → Team alerted
6.4 — Google Sheets Unreadable
Soft dependency → Log warning → "Could not read Sheets. Proceeding with SF + Shortlisting data only." → Workflow continues
Session Timeout / Interrupted Run
Detect interrupted session via state machine → Offer Partial Resume → "Previous run interrupted. 8/15 sent. Resume remaining 7?"
