# UXReach — Full Agent Capabilities List

> All use cases for Email Agent (Invite) and Daily Update Agent (Query/Status), including existing POC functionality and future planned features.

| S.No | Agent Type | Action Type | Use Case for Agent | Prompt Example | What will the agent do? | Precautions / Note |
|------|------------|-------------|---------------------|----------------|--------------------------|--------------------|
| **1** | Email Agent | Email Invite | Sending emails for already shortlisted P0 candidates | `Send 5 invites for Study 1234567` | Validates Study ID in Salesforce → fetches P0 candidates from Shortlisting App → generates personalized emails via Gemini → sends via SF Email API → updates child cases (status = Scheduling In Progress) → updates parent case notes → logs audit trail | Only P0 candidates marked "Ready to Schedule" are eligible. RC's name appears in email signature regardless of study owner |
| **2** | Email Agent | Email Invite (Scheduled) | Setting up a scheduled invite for later | `Send 5 invites for Study 1234567 tomorrow at 9 AM` | Parses natural language time → creates a scheduled task → at scheduled time, autonomously checks shortlisting tool, selects P0s, generates emails, sends them, updates cases | Emails go out only if candidates are shortlisted with P0 and marked "Ready to Schedule" at that time. If fewer P0s available than requested, sends what's available and notifies RC |
| **3** | Email Agent | Filtered Invite (Region) | Send invites to a specific country/region | `Send 5 invites for study 1234567 from Japan` | Applies region filter → selects only P0s from Japan pool → generates emails → sends. Shows breakdown before send: "5 from Japan pool of 8 P0s available" | If filter returns 0 candidates, agent aborts and tells RC no candidates match |
| **4** | Email Agent | Filtered Invite (Customer Type) | Send invites to specific customer segment | `Send 5 invites for study 1234567 to Media Agency` | Applies customer-type filter → selects only P0s matching "Media Agency" → sends | Supported types: Media Agency, Large Enterprise, SMB, Startup, Government. Aliases handled (e.g., "enterprise", "govt") |
| **5** | Email Agent | Combined Filter | Send invites with region + customer type filters | `Send 5 invites for study 1234567 from Japan, media agency` | Applies both filters (AND logic) → sends to intersection | If filter is too restrictive and returns 0, warn RC and suggest relaxing filter |
| **6** | Email Agent | Multi-Study Invite | Send invites across multiple studies in one command | `Send 5 invites for study 1234567 and 3 for study 2345678` | Queues studies → processes sequentially → shows "Study 1 of 2" progress → shows combined summary at end | If any study fails (invalid ID, no P0s), skip and continue with others. Full audit log per study |
| **7** | Email Agent | Cross-RC Invite | RC sends invites for another RC's case (leave coverage) | `Send 10 invites for study 3456789` (when study is owned by a different RC) | Detects ownership mismatch → shows warning: "This study is worked on by Mike Johnson. Are you sure?" → RC confirms → sends with current RC's name in signature | Only allowed if "Allow cross-RC sending" is enabled in Settings. All actions logged against the sending RC, not the owner |
| **8** | Email Agent | Smart ID Suggestion | Handle invalid study ID gracefully | `Send 10 invites for study 9999999` (invalid ID) | Returns: "I couldn't find study 9999999. Here are your recent studies" → lists RC's active studies as clickable buttons | Does NOT auto-suggest "Do you want me to work on this?" — RC must explicitly select to prevent typo mistakes |
| **9** | Email Agent | Study Picker UI | Visual selection when RC says "send invites" without details | `Send invites` or click "Send Invites Now" button | Opens a dropdown showing all RC's active studies with checkboxes + count inputs + remaining counts. RC selects studies and quantities → submits | Multi-select supported for batch sends across studies |
| **10** | Email Agent | Schedule Picker UI | Visual date/time picker for scheduling | `Schedule invites` or click "Schedule for later" button | Opens dropdown with study selection + date input (min today) + time input (default 9 AM) → submits as scheduled job | Date defaults to tomorrow, time defaults to 9 AM. Scheduled jobs visible in "Scheduled Invites" screen |
| **11** | Email Agent | Automated Daily Task | Hourly ping for newly shortlisted P0s | _No prompt required (automated)_ | Monitors Shortlisting App / Salesforce every hour → if new P0s marked "Ready to Schedule", sends hourly summary ping to RC in Google Chat | RC can configure ping frequency in Settings. Option to disable or set to daily digest instead |
| **12** | Email Agent | Health Check | Validate system dependencies before workflow | _Automatic before each send_ | Pings Salesforce + Gemini + Shortlisting App in parallel → if any down, blocks workflow and notifies RC. If Gemini down, offers fallback to static template | All systems must be healthy for full workflow. Graceful degradation: Gemini down → static template, SF/Shortlisting down → abort |
| **13** | Email Agent | Fallback on AI Failure | Handle Gemini API outage | _Automatic circuit breaker_ | If Gemini is unreachable → circuit breaker opens → prompts RC: "Gemini unavailable. Proceed with standard template?" → if yes, uses pre-approved static template → continues send | Pod Lead notified of degraded mode. Static template skips personalization but preserves merge fields from SF |
| **14** | Email Agent | Retry on Send Failure | Handle per-email failures | _Automatic on batch send_ | Each email tracked individually → on failure (invalid email, bounce), retries 3x with exponential backoff (1s → 2s → 4s) → if all retries fail, adds to Dead Letter Queue → RC notified | Successful sends are NOT rolled back. Partial success is acceptable and logged |
| **15** | Email Agent | Cancel Mid-Send | RC stops a send in progress | Click **Stop** button during send | Stops remaining dispatches → already-sent emails are NOT recalled → shows summary: "8 of 15 sent. 7 cancelled. Cases updated for sent only" → logs cancellation in audit | Cannot cancel individual emails, only the whole batch |
| **16** | Daily Update Agent | Response to Candidate | Assist RC in drafting replies to participant emails | AI Agent: _"We have a reply from 'John Smith' for Study 1234567. He's asking to resend the ICF link. Shall I send: http://consent-na.google.com?"_ <br><br> RC: _Yes, go ahead_ | Monitors inbox → identifies participant replies → classifies intent (ICF resend, reschedule, decline, question) → drafts response → presents to RC for approval → sends after RC confirms | RC can modify draft before sending. All drafts use RC's signature. Auto-flags sensitive requests (medical, legal) for human review |
| **17** | Daily Update Agent | EOD Update | Draft and post end-of-day updates | RC: _"Show me my EOD update for today"_ <br><br> AI Agent: _"Study 1234567: 7 interviews completed, 25 participants shortlisted, 25 invite emails sent, 5 interviews booked and yet to happen. Study 3334445: 12 interviews completed..."_ <br><br> RC: _Yes, proceed_ | Aggregates day's activity per study → drafts summary → on RC approval: (1) Updates SF case notes, (2) Pings UXRs + Pod Leads in Google Chat, (3) Emails UXRs with CC to Pod Leads | Always requires RC approval before posting. RC can edit the draft. Keeps audit of what was posted |
| **18** | Daily Update Agent | Automated Task — Booking Confirmation | Monitor calendar for new participant bookings | _No prompt required (automated)_ | Checks RC's calendar / Appointment Booking calendar → identifies new bookings → sends participant a confirmation email → includes ICF link | Agent uses the confirmation email template from SF. Count included in daily updates email and displayed in Dashboard |
| **19** | Daily Update Agent | Automated Task — Day-Before Reminder | Send reminder 24h before scheduled interview | _No prompt required (automated)_ | Runs daily scan of upcoming interviews → identifies those ≤24h away → sends reminder email with join link + interview details | Also sends ICF reminder if ICF still not signed. Does NOT remind participants who already had a reminder sent |
| **20** | Daily Update Agent | Automated Task — ICF Reminder | Nudge participants who booked but haven't signed ICF | _No prompt required (automated)_ | Runs daily scan → identifies participants with status "Scheduling In Progress" but ICF_Signed = false → sends ICF reminder email | Escalates to RC after 3 ICF reminders ignored. Blocks interview if ICF not signed by day-of |
| **21** | Daily Update Agent | Response Tracking Query | Who has responded to a study's invites? | `Who responded to study 1234567` or `responses for study 1234567` | Returns breakdown: ✅ 6 Confirmed, 📅 3 Booked (ICF pending), ⏳ 2 Recently invited, 🚫 2 No response, ❌ 2 Declined → total 15 invited | Shows actions to drill into each category. Counts pulled from SF child cases |
| **22** | Daily Update Agent | ICF Status Query | Check ICF signing status | `ICF status for study 1234567` or `who signed ICF` | Returns count signed + list of pending with booked date, shows "Send ICF reminders" action | Participants not yet booked are excluded — only booked-but-unsigned shown |
| **23** | Daily Update Agent | Reminders Needed Query | Show who needs a follow-up | `Who needs a reminder for study 1234567` | Returns two lists: **Non-responders** (invited >48h ago, no response) + **Pending ICF** (booked but not signed). Offers "Send reminders" action | Agent can auto-send reminders after RC approval. Tracks reminder count per participant |
| **24** | Daily Update Agent | Calendar Bookings Query | See who has booked interview slots | `Bookings for study 1234567` or `who booked` | Returns list of participants with booked slot datetime, interview type, and ICF status per booking | Pulls from calendar integration. Shows both confirmed (ICF signed) and tentative (ICF pending) |
| **25** | Daily Update Agent | Confirmed Count Query | Quick count of confirmed participants | `How many confirmed for study 1234567` | Returns: "6 of 45 required are fully confirmed (booked + ICF signed). 3 more are pending ICF signature" | Used by UXR for quick status checks. Does NOT include no-shows |
| **26** | Daily Update Agent | Full Study Progress | Complete progress summary per study | `Progress for study 1234567` or `study progress 1234567` | Returns comprehensive view: invited counts, booked, ICF signed, confirmed, no response, declined, needs-attention flags ("2 haven't responded in 48h+") | Used for daily standups. Export as CSV available |
| **27** | Daily Update Agent | Daily Summary | Today's activity across all RC's studies | `Today's summary` or `Show today's activity` | Returns: Studies processed today, total invites sent, success rate, failures, average time, participant status counts per study | Aggregated across all RC's studies. Filter by study via "summary for study X" |
| **28** | Daily Update Agent | Pending Studies | List studies needing more invites | `Pending studies` or `what studies need invites` | Returns studies where already_sent < total_required. One line per study: "Study 1234567 - 15/45 sent, 30 remaining" | Includes "Send invites for" quick-action button per row |
| **29** | Daily Update Agent | Failure Report | Today's failed sends | `What failed today` or `failures` | Returns detailed failure list: study, participant, error reason (invalid email, bounce, SF API timeout), retry count, resolution status | Auto-retry recommendations provided. One-click "Retry failed" action |
| **30** | Daily Update Agent | My Studies | Overview of all studies RC owns or contributes to | `My studies` or `show all my studies` | Returns full list with: total required, sent, remaining, last run date, owner status (owner vs. delegated) | Includes delegated studies (cases where other RCs delegated to current RC) |
| **31** | Daily Update Agent | Remaining Invites Query | Quick check on remaining work | `How many invites left for study 1234567` | Returns: "30 of 45 remaining. 12 P0s ready to schedule, 2 newly marked this week" | Breaks down by readiness: immediately sendable vs. pending shortlisting |
| **32** | Daily Update Agent | Scheduled Jobs Query | See upcoming scheduled sends | `My scheduled sends` or `when is my next schedule` | Returns list of scheduled jobs sorted by datetime, with study, count, and cancel button | Only shows status=scheduled (not completed or cancelled). Auto-cleans >7 days completed |
| **33** | Daily Update Agent | SLA Breach Alert | Notify when a study is behind schedule | _Automatic_ | If a study's send run exceeds 15 min → warning at 10 min, alert at 15 min → notifies Pod Lead, logs incident | Only active during a run. Not triggered by participant response delays |
| **34** | Daily Update Agent | Weekly Metrics Rollup | Week-over-week performance | `Weekly metrics` or `weekly rollup` | Returns: studies processed, total invites, success rate, confirmation rate, time saved vs manual, per-region breakdown | Useful for QBR. Export as PDF/CSV |
| **35** | Daily Update Agent | Help Command | Show available commands | `help` or `what can you do` | Returns categorized command reference: send invites, schedule, filters, queries, reminders | Grouped by agent type. Context-aware examples using RC's actual studies |
| **36** | Settings / Delegation | Case Delegation | RC delegates cases during leave | Settings → Delegate Case 1234567 to Mike Johnson | Adds delegation record → Mike can now send invites for 1234567 during leave period | Auto-expires after configurable period. Original owner gets notification when delegation is used |
| **37** | Settings / Preferences | Cross-RC Send Toggle | Allow/disallow sending for others | Toggle in Settings | Enables/disables cross-RC sending globally for the RC | Default: enabled. Audit logs which RC sent for which case |
| **38** | Audit / Compliance | Audit Trail | Immutable log of all actions | Audit Trail screen | Shows every action: sends, schedules, cancellations, delegations. Searchable by study, RC, date, status | Retained for 45 days (configurable). Summary retained permanently |
| **39** | Audit / Compliance | PII Protection | No participant PII stored in agent | _Automatic_ | Agent logs only: Study ID, RC name, count, timestamp, outcome. Participant names/emails stay in Salesforce | All logs anonymized. GDPR compliant, stateless agent |
| **40** | Email Agent | Multi-Email Types | Send correct email type per context | _Automatic based on workflow stage_ | Uses correct SF template: **Invite** (initial contact), **Confirmation** (after booking), **ICF Reminder** (if unsigned), **Day-Before Reminder** (24h before) | Templates pre-configured in Salesforce. Agent selects based on participant status |
